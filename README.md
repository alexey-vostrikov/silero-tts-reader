[![Platform](https://img.shields.io/badge/platform-Linux_(X11%2FWayland)-lightgrey.svg)](https://www.kernel.org/)

**Silero TTS Reader** — это современное, легкое и бытрое Linux-приложение для мгновенного озвучивания любого выделенного текста или содержимого буфера обмена с использованием нейросетевых моделей **Silero TTS v5**.

Приложение работает в фоновом режиме через системный трей, управляется глобальными горячими клавишами и предоставляет плавный плавающий виджет управления воспроизведением с возможностью гибкой регулировки скорости, перемотки и умной транслитерации.

## ✨ Основные возможности

- ⚡ **Мгновенное озвучивание по хоткею**: Озвучивание выделенного в любой программе текста (`Ctrl+Alt+R`) или содержимого буфера обмена (`Ctrl+Alt+C`).
- ⏯ **Плавающий оверлейный виджет**:
  - Всегда поверх всех окон без захвата фокуса ввода.
  - Интерактивный таймлайн/прогресс-бар с возможностью перехода в любой момент аудио по клику мышью.
  - Кнопки быстрой перемотки назад и вперед (`◀◀` -5с / `▶▶` +5с).
  - Поддержка динамической паузы и возобновления.
- 🤖 **Интеллектуальная транслитерация (LLM + Offline)**:
  - **ИИ-транскрипция**: Интеграция с Ollama, OpenAI API или пользовательскими REST-эндпоинтами для адаптивного перевода иностранных брендов и терминов в кириллицу с точной простановкой ударений (например, `Python` → `Па+йтон`, `Google` → `Гу+гл`).
  - **Автономный фолбэк**: Встроенный правило-ориентированный словарь и фонетический транслитератор для 100% офлайн работы при отсутствии сети.
  - **100% Автономный конвертер чисел**: Локальное превращение любых арабских цифр, чисел, дат, процентов и дробей в числительные кириллицей (`2026` → `две тысячи двадцать шесть`, `100%` → `сто процентов`).
- 🎭 **Silero TTS v5 и другие языки**:
  - Высококачественная генерация речи на русском языке (`xenia`, `kseniya`, `aidar`, `baya`, `eugene`).
  - Английский через модель `v3_en` (119 голосов `en_0`…`en_117`); язык выбирается сам по письменности текста, вручную — `--lang`, а в speech-dispatcher — по языку клиента.
  - Каталог моделей (`silero-tts-model`) знает также `de`, `es`, `fr`, `ua` — они скачиваются по требованию.
  - Режим живого предпросмотра голоса прямо в настройках.
- 🎚 **Регулировка скорости (0.5x–3.0x)**: Изменение скорости речи с сохранением естественного тона голоса — в приложении (`rubberband-cli`), из командной строки (`--rate 1.5`) и для всех клиентов speech-dispatcher (`spd-say -r 50`).
- 🎨 **Интеграция с оформлением системы**:
  - Автоматическое определение тёмной/светлой темы ОС.
  - Автоопределение и динамическое применение системного акцентного цвета (GNOME accent-color / портал Freedesktop, запасной путь — gsettings).
- 🐧 **Поддержка Wayland и X11**: Стабильная работа в Arch Linux, Ubuntu, Fedora, Debian и COSMIC Desktop.
- 🪟 **Один экземпляр и открытие файлов**: `silero-tts-reader текст.txt` и «Открыть с помощью» озвучивают файл; если запускаемая сборка новее работающей, старая закрывается штатно и место занимает новая.
- 🌍 **Интерфейс на русском и английском**: язык выбирается в настройках (`ru_RU` / `en_US` / авто из системы), строки переведены целиком.
- 📖 **Книги FB2**: открывает `.fb2` и книги в архивах — `.fb2.zip`, `.fb2.xz`, `.fb2.lzma`, `.fb2.gz`, `.fb2.bz2`, `.fb2.zst`, `.fb2.lz4`, а также сжатый `tar` (`.fb2.tar.gz`, `.fb2.tgz`, `.fb2.tar.xz`, `.fb2.txz`, `.fb2.tar.bz2`, `.fb2.tbz2`, `.fb2.tar.zst`, `.fb2.tzst`); формат определяется по содержимому, поэтому переименованный файл тоже читается.

## 🛠️ Системные требования

- **ОС**: Linux (Arch, Ubuntu/Debian, Fedora и др.)
- **Окружение**: X11 или Wayland (с включенным XWayland/evdev для глобальных хоткеев)
- **Python**: 3.10 или новее
- **Системные утилиты**:
  - `xdotool` и `xclip` — для эмуляции нажатий и считывания выделения
  - `rubberband-cli` — *(опционально)* для качественного изменения скорости речи

## 🚀 Быстрая установка

### Автоматическая установка (Рекомендуется)

Клонируйте репозиторий и запустите скрипт автоматической установки:

```bash
git clone https://github.com/Andrey4952/silero-tts-reader.git
cd silero-tts-reader
bash install.sh
```

Скрипт автоматически:
1. Определит ваш дистрибутив и установит системные зависимости (`xdotool`, `xclip`, `rubberband`).
2. Настроит права доступа udev для чтения клавиатурных событий глобальных хоткеев.
3. Скачает нейросетевую модель Silero TTS v5 (`v5_ru.pt`, ~145 МБ).
4. Создаст изолированное виртуальное окружение Python со всеми необходимыми пакетами.

### Ручная установка

#### 1. Установка системных зависимостей

* **Arch Linux / Manjaro**:
  ```bash
  sudo pacman -S xdotool xclip rubberband python-pyqt6 python-numpy python-pytorch-opt-cpu
  ```
* **Ubuntu / Debian**:
  ```bash
  sudo apt install xdotool xclip rubberband-cli python3-venv python3-pyqt6
  ```
* **Fedora**:
  ```bash
  sudo dnf install xdotool xclip rubberband python3-qt5
  ```

#### 2. Загрузка модели Silero TTS v5

```bash
mkdir -p ~/.local/share/silero-tts-reader
wget -O ~/.local/share/silero-tts-reader/v5_ru.pt \
  https://models.silero.ai/models/tts/ru/v5_ru.pt
```

#### 3. Настройка Python venv и зависимостей

```bash
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
pip install -r requirements.txt pyrubberband
```

## 📦 Сборка и установка .deb

Пакет собирается без `debhelper` — достаточно `dpkg-deb` и `python3-pil` (для иконок):

```bash
./packaging/build-deb.sh          # результат: четыре .deb в dist/
VERSION=2.0.0 ./packaging/build-deb.sh   # версию можно задать явно
```

Пакетов четыре — раскладка по назначению:

| Пакет | Что внутри |
|---|---|
| `silero-tts-common` | настройки и конфиги: `config_manager`, движок синтеза, обработка текста (`/usr/lib/silero-tts/silero_tts_reader/{config,core}`) |
| `silero-tts-reader` | GTK-приложение: `/usr/bin/silero-tts-reader`, `.desktop`, иконки, user-unit |
| `silero-tts-speechd` | командная строка: `/usr/bin/silero-tts-speak` и `/usr/bin/silero-tts-speechd` |
| `speech-dispatcher-silero-tts` | конфигурация модуля `/etc/speech-dispatcher/modules/silero-tts.conf` |

`silero-tts-common` держит общий код, остальные три зависят от него точной версией
(`silero-tts-common (= <версия>)`), так что половинчатой установки не бывает.

Версия пакета детерминирована: тег `v2.1.0` на HEAD даёт `2.1.0`, при коммитах после тега —
`2.1.0+7.gabc1234`, без тегов вовсе — `<version из pyproject.toml>+gitabc1234`, а неубранные правки
добавляют `.dirty`. Установка и удаление:

```bash
sudo apt install ./dist/silero-tts-common_*.deb ./dist/silero-tts-reader_*.deb \
                 ./dist/silero-tts-speechd_*.deb ./dist/speech-dispatcher-silero-tts_*.deb
sudo apt remove silero-tts-reader silero-tts-speechd speech-dispatcher-silero-tts silero-tts-common
```

Что ставится: общий код в `/usr/lib/silero-tts`, запускаторы `/usr/bin/silero-tts-reader` и
`/usr/bin/silero-tts-speak`, `.desktop` в `/usr/share/applications`, иконки в теме `hicolor`,
user-unit `/usr/lib/systemd/user/silero-tts-reader.service` (не включается автоматически),
конфигурация модуля speech-dispatcher.

`Depends` пакета `silero-tts-reader` — только то, что реально есть в архиве Ubuntu: `python3-gi`,
`gir1.2-gtk-4.0`, `libgtk4-layer-shell0` (угол экрана под Wayland) и `python3-xlib` (запасной путь
под X11), а также `rubberband-cli` (изменение скорости). Значок в лотке отдаётся по D-Bus
(StatusNotifierItem), поэтому отдельный пакет AppIndicator больше не нужен. Тяжёлые и необязательные для запуска `python3-torch` (движок синтеза, ~65 МБ в
пакете, ~117 МБ на диске) и `python3-sounddevice` (вывод звука), а также `python3-pynput` и
`python3-evdev` (глобальные хоткеи) — в `Recommends`: в Ubuntu 26.04 они есть в архиве, ставятся
одной командой, а запускатор проверяет их наличие и подсказывает её:

```bash
sudo apt install python3-torch python3-sounddevice python3-pynput python3-evdev
```

Сборка в CI — `.github/workflows/deb.yml`: обе джобы выполняются на `ubuntu-26.04`, а сборка идёт
внутри контейнера `ubuntu:26.04` (целевой дистрибутив). На каждый push/PR собираются оба пакета,
проверяется состав (`dpkg-deb --contents`), они ставятся на чистую систему (`dpkg -i` без
`--force-depends`), сверяется, что GTK инициализируется, запускатор даёт внятное сообщение об
отсутствующих pip-модулях, а `speech-dispatcher` загружает модуль `silero-tts`; на любой тег пакеты
прикрепляются к релизу. Локальная отладка workflow — `act`:

```bash
act -W .github/workflows/deb.yml -j deb     # конфигурация образов — в .actrc
```

## 🗣️ Интеграция со speech-dispatcher

Отдельный пакет `speech-dispatcher-silero-tts` делает голоса Silero доступными любому клиенту
speech-dispatcher: `spd-say`, Orca, режим чтения в Firefox, talkd-совместимые утилиты. Он собирается
тем же скриптом (`dist/speech-dispatcher-silero-tts_<версия>_all.deb`) и зависит от
`silero-tts-speechd` той же версии: конфигурация модуля и инструмент его включения разведены по
пакетам, чтобы обновлять их независимо.

Собственного C-модуля нет: используется штатный плагин `sd_generic`, а синтез и воспроизведение
выполняет `/usr/bin/silero-tts-speak`. Конфигурация модуля
`/etc/speech-dispatcher/modules/silero-tts.conf` лежит в `speech-dispatcher-silero-tts` (conffile),
команда управления `silero-tts-speechd` — в одноимённом пакете:

```bash
sudo apt install ./dist/silero-tts-common_*.deb ./dist/silero-tts-reader_*.deb \
                 ./dist/silero-tts-speechd_*.deb ./dist/speech-dispatcher-silero-tts_*.deb

sudo silero-tts-speechd enable     # добавить AddModule в speechd.conf (идемпотентно, с бэкапом)
silero-tts-speechd status          # подключён ли модуль
spd-say -O                         # в списке появится silero-tts
spd-say -o silero-tts -l ru "Проверка синтеза"
spd-say -o silero-tts -y FEMALE2 -l ru "Голос baya"
sudo silero-tts-speechd disable    # убрать ровно добавленный блок
```

Голоса: `FEMALE1` (xenia), `FEMALE2` (baya), `FEMALE3` (kseniya), `MALE1` (aidar), `MALE2` (eugene),
`MALE3` (random). Модулем по умолчанию модуль становится после `DefaultModule silero-tts` в
`speechd.conf`.

### Языки

`silero-tts-speak` выбирает модель по языку: сначала `--lang`, затем `tts.language` из конфига, а если
там `auto` — по письменности текста (кириллица → `v5_ru`, латиница → `v3_en`). В speech-dispatcher
язык приходит от клиента как `$LANGUAGE`, поэтому `spd-say -l en` говорит английским голосом, а
`-l ru` — русским, без настройки модуля.

Русская модель (`v5_ru.pt`, 139 МБ) в пакет не входит и качается отдельно; английская (`v3_en.pt`,
55 МБ) — тоже. Управляет этим `silero-tts-model` из пакета `silero-tts-common`:

```bash
silero-tts-model list               # что установлено, что можно скачать
silero-tts-model download en        # английская модель (55 МБ)
silero-tts-model download ru        # русская, если ещё не скачана
silero-tts-model path en            # путь к файлу модели
```

Каталог знает также `de`, `es`, `fr`, `ua` — те же 55 МБ, голоса `de_0`…, `es_0`… Сами по себе они
не подхватываются: язык у них однозначно не определяется, поэтому нужен `--lang de` и своя
`AddVoice`-строка в конфиге модуля.

Голоса модуля объявлены по типам: `FEMALE1` (ru — xenia, en — en_0), `FEMALE2` (baya, en_2),
`FEMALE3` (kseniya, en_4), `MALE1` (aidar, en_1), `MALE2` (eugene, en_3), `MALE3` (random, en_117).
Выбирать можно типом (`-t female1`) или именем объявленного голоса (`-y xenia`, `-y en_0`); если
имя не объявлено, speech-dispatcher подставит голос модуля по умолчанию, а не отклонит запрос.
Голос по умолчанию, который выбирает сам speech-dispatcher без указаний клиента, — `MALE1`, то есть
`aidar` для русского и `en_1` для английского.

Любой из 119 английских голосов доступен напрямую через CLI, минуя speech-dispatcher:

```bash
silero-tts-speak --lang en --voice en_42 "any voice of the model"
```

Чтобы такой голос стал доступен и клиентам speech-dispatcher, добавьте строку в
`/etc/speech-dispatcher/modules/silero-tts.conf` (файл — conffile, правки сохранятся при обновлении):

```
AddVoice    "en"    "MALE1"    "en_42"
```

```bash
spd-say -o silero-tts -l en "English through speech-dispatcher"
spd-say -o silero-tts -l ru "Русский через speech-dispatcher"
silero-tts-speak --wav-out /tmp/en.wav --lang en "hello"
```

### Смешанный текст: два голоса в одной фразе

С `--mixed` язык выбирается для каждого куска фразы по письменности: латинские слова читает
английская модель, кириллицу — русская. Именно это нужно для технического текста, где русская фраза
содержит английские термины:

```bash
silero-tts-speak --mixed "synthesize использует пути движка"
#   по-английски: synthesize
#   по-русски:    использует пути движка
```

Порядок сохраняется, подряд идущие слова одного языка остаются одним куском (интонация не дробится),
между кусками вставляется пауза 80 мс. Модуль speech-dispatcher запускает CLI с `--mixed`, поэтому
для всех клиентов (`spd-say`, Orca, Firefox) смешанная фраза звучит двумя голосами автоматически:

```bash
spd-say -o silero-tts "synthesize использует пути движка"
```

Голос берётся из запроса клиента для его языка, а для второго языка — голос по умолчанию этой модели
(например, `xenia` для русского и `en_0` для английского). Если английской модели нет, латиница
читается русскими фонемами — команда не падает.

Включить смешанный режим по умолчанию для CLI (без флага): `"mixed": true` в секции `tts` конфига.

### Выбор голоса

В настройках голоса разделены по языкам, а сверху есть поиск: у английской
модели 119 голосов (`en_0`…`en_117`), и найти `en_42` перебором нельзя — введите
`42` в поле поиска. Выбор запоминается отдельно для каждого языка.

### Скорость речи

Скорость меняет `rubberband-cli` (он в `Depends`), поэтому тон голоса не плывёт. Раньше код требовал
ещё и Python-обёртку `pyrubberband`, которой в архиве Ubuntu нет, — из-за этого регулировка молча не
работала в установленной системе.

```bash
silero-tts-speak --rate 1.5 "быстрее в полтора раза"     # 0.5–3.0
silero-tts-speak --rate 0.75 "медленнее"
spd-say -o silero-tts -r 50 "быстрее"                    # шкала speech-dispatcher
spd-say -o silero-tts -r -30 "медленнее"
```

В speech-dispatcher темп приходит как `$RATE` в шкале −100…+100. CLI переводит его в множитель:
`0 → 1.0`, `+100 → 2.0`, `−100 → 0.5` (линейно, отрицательная половина — до 0.5). Скорость из
`--rate` важнее `--spd-rate`, а если не задано ни то ни другое — берётся `playback.speed` из конфига.

В приложении скорость задаётся в настройках (0.5–3.0 шагом 0.25) и меняется на лету: каждый сегмент
растягивается перед подачей в звуковую карту. Без `rubberband-cli` приложение не молчит, а сообщает,
что изменение скорости недоступно, и говорит в обычном темпе.

Темп и высота тона не передаются: модели Silero их не поддерживает, а целочисленный `$RATE`
speech-dispatcher дал бы бессмысленную скорость. Ограничения прямые: без установленных `torch`,
`sounddevice` и модели нужного языка (`silero-tts-model list`) `silero-tts-speak` завершится
кодом 1 с понятным сообщением, и speech-dispatcher напишет его в свой лог.

### Установка в систему и автозапуск

Для добавления приложения в меню приложений вашей ОС и автозапуска при входе в систему:

```bash
# Создание бинарного ярлыка в ~/.local/bin и .desktop файла
mkdir -p ~/.local/bin ~/.local/share/applications ~/.config/autostart

cat << 'EOF' > ~/.local/bin/silero-tts-reader
#!/usr/bin/env bash
exec /path/to/silero-tts-reader/.venv/bin/python /path/to/silero-tts-reader/run.py "$@"
EOF
chmod +x ~/.local/bin/silero-tts-reader

cp silero-tts-reader.desktop ~/.local/share/applications/
cp silero-tts-reader.desktop ~/.config/autostart/
```

Также доступен юнит **systemd** для фонового демона:
```bash
cp silero-tts-reader.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now silero-tts-reader.service
```

## 🪟 Один экземпляр, открытие файлов, замена сборки

Приложение работает в одном процессе: второй запуск поднимает окно уже
работающего, а не создаёт второй трей и второй загрузчик модели.

Если запускаемая сборка **новее** работающей, работающая закрывается штатно
(сохраняет конфиг, снимает иконку с шины) и её место занимает новая. «Новее»
определяется по метке сборки, а не по версии пакета: при правке кода без смены
тега версия та же, а сборки разные. Метка пишется при сборке пакета в
`/usr/lib/silero-tts/build-info.json`; при запуске из репозитория берётся время
последнего коммита. Если сборки одинаковые или работающая новее — ничего не
закрывается.

```bash
silero-tts-reader                  # обычный запуск
silero-tts-reader заметка.txt      # озвучить файл (.txt .md .log .csv .json …)
silero-tts-reader book.fb2.zip     # озвучить книгу
silero-tts-reader a.txt b.md       # несколько файлов подряд
```

Файл читается в UTF-8, при неудаче — в cp1251 (старые русские тексты). Бинарники
и неизвестные расширения не открываются: вместо мусора в динамике — понятное
сообщение. «Открыть с помощью» работает через `MimeType` в `.desktop`:
`text/plain`, `application/x-fictionbook+xml`, `application/x-zip-compressed-fb2`.

## 📖 Книги FB2

Книга читается как обычный текст: заголовок с автором, затем абзацы, эпиграфы,
стихи и подзаголовки; картинки, таблицы оформления и `base64` из `<binary>`
отбрасываются.

| Формат | Как определяется |
|---|---|
| `.fb2` | XML книги (UTF-8, windows-1251, UTF-16 с BOM) |
| `.fb2.zip`, `.fbz` | zip; внутри ищется книга, в том числе `.fb2.xz` |
| `.fb2.xz` | xz |
| `.fb2.lzma` | старый lzma без заголовка |
| `.fb2.gz`, `.fb2.bz2` | gzip, bzip2 |
| `.fb2.zst` | zstd: из коробки в Python 3.14, иначе `python3-zstandard`, иначе утилита `zstd` |
| `.fb2.lz4` | LZ4-фрейм, включая связанные блоки, и старый legacy-формат |
| `.fb2.tar.gz`, `.fb2.tgz` | tar в gzip |
| `.fb2.tar.xz`, `.fb2.txz` | tar в xz |
| `.fb2.tar.bz2`, `.fb2.tbz2` | tar в bzip2 |
| `.fb2.tar.zst`, `.fb2.tzst` | tar в zstd |
| `.fb2.tar.lzma` | tar в старом lzma |
| `.fb2.tar` | голый tar — вырожденный случай: для одной книги выгоды не даёт, поддержан «на всякий случай» |

Контейнер определяется **по магии файла**, а не по расширению: коллекции книг
часто содержат `xz`, переименованный в `.fb2`, и наоборот. У tar магия стоит не в
начале файла, а на 257-м байте, и притом у разных реализаций она разная: `ustar`
у POSIX и pax, `ustar ` (с пробелом) у GNU, а у старого v7 её нет вовсе — только
контрольная сумма заголовка. Поэтому tar опознаётся и по слову `ustar`, и по
сходящейся контрольной сумме; иначе `.fb2.tar.gz` не узнаётся после распаковки
внешнего слоя. Вложенные контейнеры разворачиваются по очереди, до четырёх
уровней: `.fb2.tar.gz` внутри `.zip` читается.

Если под расширением `.fb2` лежит сохранённая веб-страница, приложение так и
скажет — вместо «файл повреждён».

### Как книга читается: потоком, главами

Длинный текст не обрезается — книга читается целиком и последовательно. Границы
выбраны так: **не больше главы за раз и не меньше строки**.

* кусок для обработки — одна глава (заголовки `Глава`, `Часть`, `Закон`,
  `Правило`, `Пролог`, `Эпилог`, `Chapter`, `Part`, `Rule`, а также
  `#`-заголовки Markdown); если глава длиннее 4 000 символов, она режется по
  строкам-абзацам;
* строка — минимальная единица, обычная строка не разрывается; аномально
  длинная строка (больше 4 000 символов, то есть сбой вёрстки) режется на
  примерно равные части по стыкам предложений, а если предложений нет — по
  стыкам слов; одно слово длиннее лимита остаётся целым, дробить его нечем;
* квант воспроизведения — **предложение**: каждое синтезируется и играется
  отдельно, поэтому паузы на границах фраз естественные, а не «по сколько
  влезло». Строка как квант плоха — в абзаце их несколько и фраза рвётся;
* строки берутся квантом только когда предложений нет вовсе (заголовок,
  список, стихи без точек), и тогда короткие строки склеиваются;
* одно предложение длиннее 800 символов режется по словам; соседние
  предложения ради ровных сегментов не склеиваются — это ломает паузы;
* очередь готового звука ограничена шестью сегментами: синтез идёт в темпе
  проигрывания и не держит в памяти часы аудио.

Остановка работает сразу: очередь, синтез и воспроизведение завершаются вместе.

## 🌍 Язык интерфейса

Язык выбирается в настройках (`ru_RU` / `en_US` / «авто из системы») и через
`ui.language` в конфиге. Приоритет: явный выбор, затем `LANGUAGE`/`LC_ALL`/
`LC_MESSAGES`/`LANG`, затем русский — приложение русское по происхождению, и
молча переключать уже настроенных пользователей нельзя.

Строки исходного кода написаны по-русски и служат `msgid`; английский каталог
лежит в `locale/en_US/LC_MESSAGES/silero-tts-reader.mo`. Переводятся все
пользовательские строки: надписи, подсказки, меню, сообщения об ошибках и
справка `silero-tts-speak`. Строки журнала (`[TTSEngine]`, `[TTSWorker]` и
подобные) остаются русскими намеренно — это отладочный вывод в консоль, а не
интерфейс; такие места помечены в коде как `i18n: нет перевода`.

Проверки, встроенные в сборку и CI:

```bash
python3 packaging/i18n-wrap.py     # обернуть новые строки и пересобрать .pot
python3 packaging/i18n-build.py    # собрать .mo; падает, если .pot устарел
python3 packaging/i18n-audit.py    # падает, если есть непереведённая строка
```
